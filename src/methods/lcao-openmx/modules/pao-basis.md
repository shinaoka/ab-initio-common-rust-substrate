# PAO basis and real spherical harmonics

> Status: prototype (awaiting review)

## Overview [Public]

The basis functions of OpenMX are products of numerically given radial functions and real spherical harmonics
(manual Sections 12.1 and 12.2, technical note 14).

$$
\phi\_{I,l\zeta m}(\mathbf r) = R^{(I)}\_{l\zeta}(r)\\, S\_{lm}(\hat{\mathbf r}),\qquad r = \lVert \mathbf r \rVert
$$

- The radial functions are constructed from the ground and excited states of the Kohn–Sham equation of a pseudo-atom with an added confinement potential
  (technical note 14, PRB **69**, 195113). They are generated by ADPACK; the OpenMX main program only reads the pre-generated tables.
- The radial functions vanish outside the cutoff radius \\( r\_c \\) (manual Section 12.1). Hence the matrices vanish for atom pairs whose interatomic distance
  exceeds \\( r\_{c,I} + r\_{c,J} \\).
- Values at arbitrary \\( r \\) are obtained by interpolating the table (manual Section 12.1).

## Basis specification

### String format [Public]

The basis is specified in the `Definition.of.Atomic.Species` block of the input file by a string such as `C6.0-s2p2d1`
(manual Sections 8.2 and 12.1).

- Before `-` (`C6.0`): the PAO file name without the extension `.pao`. The file is in the data directory for PAO.
- After `-` (`s2p2d1`): the number of radial functions \\( N\_l \\) used for each angular momentum. In this example, 2 for s, 2 for p, and 1 for d.

The total number of basis functions is \\( \sum\_l (2l+1) N\_l \\). In the above example, \\( 2 + 2\cdot 3 + 1\cdot 5 = 13 \\).

When orbital optimization is used, one writes "number of original radial functions `>` number after contraction", as in `s3>2` (manual Sections 8.2 and 26).
`s1>1` without contraction means the same as `s1`. The method and input for orbital optimization are in Section 5 of [Wannier functions, unfolding, and local orbital analysis](wannier-unfolding.md).

### Interpretation of the string [Convention]

- The `6.0` in the name is merely a naming convention. The cutoff radius used in the calculation is the value of `radial.cutoff.pao` in the PAO file.
- The angular-momentum letters are `s`, `p`, `d`, `f`, `g` (\\( l = 0,\dots,4 \\)). The number following a letter is \\( N\_l \\).
  For any \\( l \\) not written, \\( N\_l = 0 \\).
- The maximum angular momentum \\( l\_{\max} \\) of a species is the largest \\( l \\) with \\( N\_l > 0 \\).
  \\( N\_l = 0 \\) is allowed for intermediate \\( l \\) (e.g. `s2d1` has no p orbitals).
- It is an error if \\( l\_{\max} \\) exceeds `PAO.Lmax` of the file, or if \\( N\_l \\) exceeds `PAO.Mul` of the file.

### Radial functions selected from the file [Convention]

For each \\( l \\), the **first** \\( N\_l \\) of the radial functions stored in the file
(multiplicities \\( \zeta = 0, 1, \dots, N\_l - 1 \\)) are used. No reordering or selection is done.

In the distributed optimized PAO files (manual Section 12.3), the leading columns of the table are already the optimized (contracted)
radial functions. Therefore, an optimized basis is obtained simply by taking them from the beginning.
The `<Contraction.coefficients…>` blocks are handled as described [below](#contraction-coefficient-block-convention) and are not used when reading.

## Ordering of orbitals on an atom [Convention]

The basis functions on one atom are ordered in the following nested order (from outermost).

1. Angular momentum \\( l = 0, 1, \dots, l\_{\max} \\)
2. Multiplicity \\( \zeta = 0, 1, \dots, N\_l - 1 \\)
3. Components of the real spherical harmonics (in the order [below](#real-spherical-harmonics-convention), \\( 2l+1 \\) of them)

That is, the indices within an atom form chunks of \\( 2l+1 \\) per \\( (l, \zeta) \\).
For `C6.0-s2p2d1`, they are the following 13.

| Index | Orbital |
|---|---|
| 0 | \\( s, \zeta=0 \\) |
| 1 | \\( s, \zeta=1 \\) |
| 2–4 | \\( p, \zeta=0 \\): \\( x, y, z \\) |
| 5–7 | \\( p, \zeta=1 \\): \\( x, y, z \\) |
| 8–12 | \\( d, \zeta=0 \\): \\( 3z^2-1,\ x^2-y^2,\ xy,\ xz,\ yz \\) |

[Convention] The atom-pair blocks of the overlap matrix, the Hamiltonian, etc. (see [sparse block format](../design/sparse-block-format.md))
use this intra-atom ordering for both rows and columns. The scfout file (manual Section 70.1) also
writes the atom-pair blocks in this ordering. When orbital optimization is used, the contracted basis is ordered by the same rule.

When a global index is needed, the chunks of each atom are concatenated in the order of atoms in the input file [Convention].

## Real spherical harmonics [Convention]

The complex spherical harmonics \\( Y\_{lm} \\) follow the standard definition with the Condon–Shortley phase
([DLMF 14.30.1](https://dlmf.nist.gov/14.30.E1)).
The real spherical harmonics \\( S\_{lm} \\) are orthonormal and, as polynomials in the unit vector \\( \hat{\mathbf r} = (x, y, z) \\),
take the following signs (all coefficients positive) and ordering.

| \\( l \\) | Ordering (component index 0, 1, …) |
|---|---|
| 0 | \\( 1/\sqrt{4\pi} \\) |
| 1 | \\( x,\ y,\ z \\) (coefficient \\( \sqrt{3/4\pi} \\)) |
| 2 | \\( 3z^2-1,\ x^2-y^2,\ xy,\ xz,\ yz \\) |
| 3 | \\( z(5z^2-3),\ x(5z^2-1),\ y(5z^2-1),\ z(x^2-y^2),\ xyz,\ x(x^2-3y^2),\ y(3x^2-y^2) \\) |
| \\( \ge 3 \\) | Components in the order proportional to \\( m=0 \\), \\( \cos\varphi \\), \\( \sin\varphi \\), \\( \cos 2\varphi \\), \\( \sin 2\varphi \\), …, \\( \cos l\varphi \\), \\( \sin l\varphi \\) |

**Note**: only for d orbitals (\\( l=2 \\)), the \\( \cos 2\varphi \\) and \\( \sin 2\varphi \\) components
(\\( x^2-y^2 \\), \\( xy \\)) come right after \\( m=0 \\), followed by the \\( \cos\varphi \\) and \\( \sin\varphi \\) components
(\\( xz \\), \\( yz \\)). The order differs from the general rule for \\( l \ge 3 \\).

The normalization coefficient of each component is the positive number determined by \\( \int d\Omega\\, S\_{lm} S\_{lm'} = \delta\_{mm'} \\).
The coefficients of the d orbitals are, in order, \\( \sqrt{5/16\pi},\ \sqrt{15/16\pi},\ \sqrt{15/4\pi},\ \sqrt{15/4\pi},\ \sqrt{15/4\pi} \\).

The transformation from complex to real can be written, for each \\( l \\), with a \\( (2l+1)\times(2l+1) \\) unitary matrix \\( U^{(l)} \\) as
\\( S\_{l\mu} = \sum\_m U^{(l)}\_{\mu m} Y\_{lm} \\). \\( U^{(l)} \\) is uniquely determined by the table above.

## PAO file format [Convention]

### Lexical structure

A PAO file (extension `.pao`) is a text format. It consists of line-oriented keywords and
blocks that start with `<name` and end with `name>`. Everything after `#` is a comment.
Keywords are looked up as the first word of a line, case-insensitively. If the same keyword appears multiple times, the first line is used.

The file also contains, verbatim, the ADPACK input used for generation and a log of the calculation.
Keywords therein (`maxL.pao`, `num.pao`, etc.) are records of the generation settings and are not read by OpenMX.

### Items read in the reimplementation

| Keyword or block | Meaning |
|---|---|
| `AtomSpecies` | Atomic number (may be fractional for virtual atoms). Used to check consistency with the VPS file |
| `PAO.Lmax` | Maximum angular momentum of the stored radial functions |
| `PAO.Mul` | Number of radial functions stored for each \\( l \\) (common to all \\( l \\)) |
| `radial.cutoff.pao` | Cutoff radius \\( r\_c \\) (bohr). Default 5.0 if absent |
| `grid.num.output` | Number of radial grid points |
| `<valence.charge.density` … `>` | Atomic valence electron density (used in the [neutral-atom potential](neutral-atom.md) chapter) |
| `<pseudo.atomic.orbitals.L=l` … `>` | Table of radial functions with angular momentum \\( l \\) (\\( l = 0,\dots, \\) `PAO.Lmax`) |

Other blocks (contraction coefficients, list of eigenvalues, copy of the ADPACK input, etc.) may be skipped.
The exception is core-hole calculations, which use the list of eigenvalues starting with `Lmax=` (the eigenvalue table) for the penalty term (Section 5 of [ESM, external electric field, and core levels](esm-field-corehole.md)).

### Table of radial functions

Each row contains \\( x = \ln r \\), \\( r \\) (bohr), followed by the values \\( R\_{l\zeta}(r) \\) for \\( \zeta = 0, 1, \dots, \\) `PAO.Mul`\\( -1 \\)
(`PAO.Mul` + 2 numbers per row).

- The values are \\( R(r) \\) itself, not \\( r R(r) \\).
- The grid is equally spaced in \\( \ln r \\). The valence-density block and the block of each \\( l \\) use the same grid.
- The grid extends beyond \\( r\_c \\), and values for \\( r > r\_c \\) are written as 0.

Example distributed files (C6.0, H5.0): 500 points, \\( r\_{\min} \approx 4\text{–}6\times 10^{-4} \\) bohr,
and the last point is about 0.9 bohr outside \\( r\_c \\).

### Normalization and orthogonality

[Convention] Radial functions with the same \\( l \\) satisfy \\( \int\_0^\infty dr\\, r^2 R\_{l\zeta} R\_{l\zeta'} = \delta\_{\zeta\zeta'} \\).
This is because the original PAOs are different eigenstates of the same radial equation and hence orthogonal, and the optimized functions are built by an orthogonal transformation of them.
Computed from the table by the trapezoidal rule, this holds to about \\( 10^{-4} \\) for the distributed files (`tools/check_pao_file.py`).
OpenMX does not renormalize on reading. The reimplementation also uses the table values as they are [Design].

### Contraction-coefficient block [Convention]

At the beginning of an optimized PAO file there are `number.optpao` and
blocks such as `<Contraction.coefficients1` … `>`, `<Contraction.coefficients2` … `>`.
These are records from when the file was created.

- Each block is the result of one orbital optimization, and each row holds \\( l \\), the contracted index, the index \\( p \\) of the original PAO, and the coefficient.
- The tool that creates the file reads the blocks in order and, for each \\( l \\), assigns the contracted functions from the beginning.
  The remaining indices use the original PAOs as they are; for each \\( l \\), the coefficient vectors are orthonormalized by Gram–Schmidt, and then
  the linear combinations of the original PAOs are written into the table.
- As a result, the `<pseudo.atomic.orbitals.L=l` tables are functions that are **already contracted and orthogonalized**.

The OpenMX main program does not read the contraction-coefficient blocks. The reimplementation does not need to read them either.

### PAO files written by OpenMX itself [Convention]

The contracted PAO file written by OpenMX itself via `CntOrb.fileout` (Section 5.6 of [Wannier functions, unfolding, and local orbital analysis](wannier-unfolding.md))
differs from the distributed optimized files above in the following respects.

- The columns after the contracted functions are **the primitive functions themselves**, not orthogonalized against the contracted functions (in the distributed files they are orthogonalized by Gram–Schmidt).
  This has no effect as long as only functions up to the contraction number \\( N\_l \\) are used, but note that they are not orthogonal when reading beyond the contraction number.
- The coefficient block is named `<Contraction.coefficients` without a number, and each row has the form `Atom= L= Mul= p= coefficient` (a different format from `<Contraction.coefficients1` etc. in the distributed files).
  This block is also not read by the OpenMX main program.
- The eigenvalue table starting with `Lmax=` is copied unchanged from the original file and is used for the core-hole penalty term ([ESM, external electric field, and core levels](esm-field-corehole.md)).

## Values outside the grid [Convention]

Outside the range of the table, values are treated as follows.

| Range | Value |
|---|---|
| \\( r < r\_{\min} \\) (inside the first grid point) | \\( l = 0 \\): the value at the first grid point \\( R\_{l\zeta}(r\_{\min}) \\). \\( l \ge 1 \\): 0 |
| \\( r\_{\min} \le r \le r\_{\mathrm{last}} \\) | Interpolation of the table |
| \\( r > r\_{\mathrm{last}} \\) (outside the last grid point) | 0 |

- Since \\( R\_l(r) \propto r^l \\) near the origin, this is a physically natural treatment. Since \\( r\_{\min} \\) is below \\( 10^{-3} \\) bohr,
  the effect of the inner treatment on integrals is negligible.
- For \\( r\_c < r \le r\_{\mathrm{last}} \\), the table values are 0, so the interpolated values are also nearly 0.
  [Design] The reimplementation may return exactly 0 for \\( r \ge r\_c \\).

[Design] The interpolation scheme is not prescribed. Since bitwise agreement is not required, any sufficiently smooth interpolation is fine
(e.g. cubic spline in the variable \\( \ln r \\), or piecewise cubic Hermite interpolation).
The existing implementation also uses piecewise cubic interpolation.
